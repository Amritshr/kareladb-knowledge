Aggregate functions

Make one value from many rows: count, sum, avg, min, max, first, last, median, percentile, vwap, twap, conditional counts and sums, the row of the maximum, and lists of text.

  • Category: Functions — aggregate
  • Keywords: aggregate, group, total, average, mean, count rows, how many, number of rows, biggest, smallest, highest, lowest, open high low close, candle, turnover, count(), distinct count, uniq, quantile, p90, p95, volume weighted average price, implicit GROUP BY, HAVING, aggregate in WHERE, conditional count, countif, COUNT FILTER, sumif, SUM FILTER, averageif, multiply all, all true, any true, bool_all, row of the maximum, day of the highest close, row of the minimum, group_concat, join text, comma list, collect list, JSON array, jsonb_agg, JSON object, jsonb_object_agg, weighted average, SUMPRODUCT, time weighted average price, TWAP, any_value, arbitrary
  • See also: GROUP BY and HAVING, SAMPLE BY, Statistics functions, Window and series functions (aggregates), Conditional and NULL functions (coalesce), Candles cookbook, PIVOT

An aggregate function reads many rows and gives back one value. For example, sum(quantity) adds up the quantity of every row.

  • With GROUP BY (or SAMPLE BY) you get one result row for each group. A group is all the rows with the same key, for example the same symbol.
  • Without GROUP BY, all rows are one group, and you get one row.
  • Implicit GROUP BY: like QuestDB, KarelaDB groups by itself. Every select item that is not inside an aggregate becomes a group key. SELECT symbol, max(high) FROM ochl_day gives one row per symbol.
  • Aggregates skip NULL values. avg of 10, NULL and 20 is 15. Only count(*) counts every row, and first and last take the first / last row's value even when it is NULL (as in QuestDB; first_not_null and last_not_null skip NULLs).
  • On no rows (without GROUP BY) count gives 0 and the others give NULL. With GROUP BY, no rows give no groups.
  • Aggregates can only be in the select list and in HAVING. To keep only some groups, use HAVING (group-by), not WHERE.
  • GROUP BY can use a name from the select list (GROUP BY band when band is an alias) or a position: GROUP BY 1 is the first column, as in PostgreSQL.
  • Put OVER (...) after an aggregate to get a running total or a moving value for every row instead of one row per group (window functions).
  • More aggregates have their own pages: spread and shape (statistics), correlation and regression (correlation), Sharpe ratio and drawdown (returns and risk), and xnpv, xirr (finance).

count(*)

Syntax:

count(*)
count()

The number of rows. NULL values do not matter here: every row counts. count() without * is the same (QuestDB style).

  • Returns: LONG.
  • NULL: rows with NULL values are counted too.
  • Notes: on no rows, count(*) is 0 (without GROUP BY). With GROUP BY, a group with no rows does not exist, so you do not get a 0 row for it.

sum

Syntax:

sum(x)

The total of all values of x.

ArgumentTypeMeaning
xany numberthe value to add up
  • Returns: LONG when every value is a whole number, an exact DECIMAL when every value is a DECIMAL (with the largest scale of them), else DOUBLE.
  • NULL: NULL values are skipped. When there are no values (or all are NULL), the result is NULL, not 0. Write coalesce(sum(x), 0) to get 0 (coalesce); for a DECIMAL(2) column write coalesce(sum(x), CAST(0 AS DECIMAL(2))), because a plain 0 is a LONG.
  • Notes: a LONG total too big for 64 bits (more than about 9.2e18) is an error: sum() is out of range (SQLSTATE 22003). A DECIMAL total is exact up to 38 digits, also past 64 bits; only past that is it an error. It never comes back rounded. For an approximate total add DOUBLE values: sum(x::DOUBLE). Text gives an error (sum needs numbers). For money, use DECIMAL(2) columns: their sum is exact.
  • DOUBLE totals: a DOUBLE total is compensated (the Neumaier method): the rounding error of each step is carried along and added back, so the total does not depend on the order of the rows and is as close to the exact total as a DOUBLE can be. QuestDB's plain sum adds without this, so its last digit can differ: five NEPSE volumes that add up to exactly 55128735 give 55128734.99999999 there. QuestDB's ksum and nsum give KarelaDB's answer; KarelaDB accepts both names as sum.

avg

Syntax:

avg(x)

The average (mean): the sum of the values divided by how many values there are.

ArgumentTypeMeaning
xany numberthe value
  • Returns: DOUBLE, also for LONG input. For DECIMAL input an exact DECIMAL with at least 16 significant digits, as in PostgreSQL: avg of 1.50 and 2.50 is 2.0000000000000000. Use round(avg(x), 2) for a report (round).

first

Syntax:

first(x)

The value of x in the earliest row. On a time-series table, earliest means the smallest time. first(open) is the open price of a candle.

ArgumentTypeMeaning
xany typethe value to take
  • Returns: the type of x.
  • NULL: the earliest row's value, even when it is NULL, as in QuestDB. To skip NULLs, use first_not_null. No rows give NULL.
  • Notes: the order is the table's time column, not ORDER BY. On a relational table (no time column) it is the order of the primary key. When many rows have the same time, KarelaDB takes the first in storage order; do not count on which one.
  • Changed 2026-09-25: before, first and last skipped NULLs (what first_not_null and last_not_null do now).

first_not_null, last_not_null

Syntax:

first_not_null(x)
last_not_null(x)

The value of x in the earliest / latest row where x is not NULL (QuestDB). Use them when a missing value must not become the answer, for example a candle whose first minute has no open price yet.

ArgumentTypeMeaning
xany typethe value to take
  • Returns: the type of x.
  • NULL: rows where x is NULL are skipped. When every value is NULL (or there are no rows), the result is NULL.
  • Notes: same order rules as first. They work with GROUP BY, SAMPLE BY and OVER (...).
  • any_value(x), arbitrary(x): the names PostgreSQL 16, DuckDB and Trino use for "some non-NULL value of the group". KarelaDB reads them as first_not_null(x), so the answer is the earliest non-NULL value, never a random one.

median

Syntax:

median(x)

The middle value: half of the values are smaller, half are bigger. With an even number of values, it is the average of the two in the middle. Unlike avg, one very big trade does not move the median much.

  • Returns: DOUBLE.
  • NULL: NULL values are skipped. No values give NULL.
  • Notes: the same as percentile(x, 0.5). KarelaDB keeps all values of a group in memory to find it.

percentile

Syntax:

percentile(x, p)

The value below which a part p of the values lie. percentile(x, 0.9) is the value that 90% of the values are at or below. Between two values, KarelaDB goes the right part of the way from one to the other (linear interpolation, like PostgreSQL percentile_cont).

ArgumentTypeMeaning
xany numberthe values
pnumberthe part, from 0 to 1 (0.9). A number above 1 is read as a percent (90 means 0.9)
  • Returns: DOUBLE.
  • NULL: NULL values of x are skipped. No values give NULL.
  • Notes: p below 0 is taken as 0 (the smallest value); a percent above 100 is taken as 100. Careful: 1 means 100%, but 1.5 means 1.5%. p is read once, from the first row. A p that is not a number is an error.

twap

Syntax:

twap(price, time)

The time-weighted average price. Each price counts for the time until the next price. A price that stayed for 2 hours counts twice as much as a price that stayed for 1 hour. Traders use TWAP to judge a price when trades came at uneven times, for example live price snapshots.

ArgumentTypeMeaning
pricenumberthe price
timeTIMESTAMP, DATE or whole number (milliseconds)when this price started
  • Returns: DOUBLE.
  • NULL: a row where price or time is NULL is skipped. No rows give NULL.
  • Notes:
    • The rows are sorted by time first; the order in the table does not matter.
    • The last price has no time after it, so it gets no weight (it is only used when it is the only price).
    • When every price has the same time, the result is the plain average.
    • Unlike vwap, the volume does not matter. With prices at even steps (one-minute candles) TWAP is almost the plain average.

Example: Live prices came at 11:05, 13:00 and 14:59: TWAP against the plain average (sample data: sample)

SELECT symbol, round(twap(ltp, timestamp), 2) AS twap, round(avg(ltp), 2) AS plain_avg
FROM live_data
GROUP BY symbol
ORDER BY symbol;

Syntax:

weighted_avg(x, weight)

The weighted average: sum(x × weight) / sum(weight). A row with weight 2 counts twice as much as a row with weight 1. wavg is the same function.

ArgumentTypeMeaning

sum_if

Syntax:

sum_if(x, condition)

Adds up x only in the rows where the condition is true. Shorter than sum(CASE WHEN condition THEN x END).

ArgumentTypeMeaning
xany numberthe value to add
conditiontrue/falsewhich rows to add
  • Returns: LONG when every added value is a whole number, DECIMAL when they are all DECIMAL of the same scale (money stays exact), else DOUBLE.

json_object_agg, jsonb_object_agg

Syntax:

json_object_agg(key, value)
jsonb_object_agg(key, value)

Collects the rows into one JSON object: the key of each row, and its value. {"CITY":513,"COAST":287.5}.

ArgumentTypeMeaning
keyany type but JSONthe key; a number becomes text (1 gives "1")
valueany typeits value; JSON stays JSON
  • Returns: JSON. jsonb_object_agg keeps each key once, with the last value given; json_object_agg keeps every pair. Postgres clients get jsonb_object_agg as jsonb ({"a": 1, "b": 2}, keys in jsonb order).
  • NULL: a NULL value becomes JSON null. A NULL key is an error (SQLSTATE 22023), as in PostgreSQL. No rows give NULL.
  • Notes: ORDER BY inside the call sets the order of the keys: jsonb_object_agg(k, v ORDER BY k). PostgreSQL writes json_object_agg as { "a" : 1 }; KarelaDB keeps JSON compact: {"a":1}.
