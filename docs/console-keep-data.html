Keep data page (how long tables keep their rows)

See every table of a database with how long it keeps its rows, and set "keep only the last N months or years": the older days, months or years are dropped, the newest stay.

  • Category: Web console
  • Keywords: keep data, retention, Save disk, /api/disk, disk usage, older copies, trash, keep the last, keep only, old data, drop old data, TTL, months, years, drop partition older than, disk space, save disk, free space, purge
  • See also: Web console, ALTER, RENAME and DROP TABLE, Timers, Partitions, SORT BY and DEDUP KEY, Databases and the data folder, View data page (browse and edit rows)

The Keep data page of the web console (Home menu) lists every table of the chosen database and lets you say how long each keeps its rows. Nothing is dropped from the start of the table: it keeps the newest data and lets the oldest go.

The period is a number and a unit: days, weeks, months or years.

  • Only time-series tables with PARTITION BY DAY, MONTH or YEAR can keep "the last N": everything else has no partitions to drop, is listed greyed, and keeps everything. Use DELETE there.
  • A partition goes when its last moment is older than the period, so "the last 6 months" always holds at least 6 full months. Months and years follow the calendar.
  • Whole partitions go, never single rows, and a dropped partition cannot be brought back. Every drop is written to the audit log.
  • A read user sees the page; the buttons need write.

Disk space

The box at the top says what the database takes on disk, part by part. It reads GET /api/disk, which walks the trash folder, so it is asked for on this page only. Hover a part to see how many files it holds.

PartWhat it isField of /api/disk
On diskeverything below togethertotal_bytes
datathe current version of every data file: the rows. Of those, tail files are rows appended after a partition's file, folded back into it later, and delta files the rows of a partition replaced or deleteddata_bytes, data_files; tails tail_bytes, tail_files; deltas delta_bytes, delta_files
older copiesolder versions of the data files, kept so a damaged file can be repaired from one of them (2 per file unless keep_versions says otherwise; a version whose old log is gone can repair nothing and goes by itself)previous_bytes, previous_files
trashreplaced files nothing needs any more; the server removes them by itself once they are older than trash_keep_hours (1 hour unless set), or when the trash is over trash_max_mb (a quarter of the data, at least 256 MB, unless set)trash_bytes, trash_folders
logthe current log, and old log kept for repairs and backups (wal_archive)wal_bytes + wal_archive_bytes

Save disk (admin) runs PURGE VERSIONS KEEP 1, which leaves one older copy per file, then PURGE TRASH, and shows the space that came back. Dropping partitions frees their files the same way: they go to the trash first, and the trash goes on its own.

Example: What the Keep button runs

Setup:

CREATE TABLE trades (time TIMESTAMP, symbol SYMBOL, qty LONG) TIMESERIES(time) PARTITION BY MONTH;
ALTER TABLE trades SET TTL 6 MONTHS;
SHOW CREATE TABLE trades;

Result:

ALTER TABLE trades SET TTL 6 MONTHS

table 'trades' drops partitions older than 6 MONTHS

SHOW CREATE TABLE trades
