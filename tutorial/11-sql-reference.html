11. SQL reference

  • Category: Tutorial

What you will learn

  • The exact form of every KarelaDB statement.
  • Every type, function and operator, with a short example.
  • The time rules, reserved words and limits.

This is a short reference. Chapters 3 to 5 explain everything with longer examples. In the syntax, [x] means "x is optional", a | b means "a or b", and ... means "more of the same".

The example results in this chapter are real. They come from examples/11-sql-reference/.

General rules

RuleDetail
StatementsEnd with ;. Many statements can be sent at once. Each one is saved on its own (statements between BEGIN and COMMIT, and a whole CALL, are saved together); KarelaDB stops at the first error.
CaseKeywords, table names, column names and function names do not care about case. Text values do ('CITY' is not 'city').
NamesLetters, digits, _, and non-English letters. A reserved word or a special name must be in double quotes: "order".
TextIn single quotes: 'CITY'. A quote inside is doubled: 'City''s'.
Numbers42, -7, 512.45, 1.5e3. Integers from -9223372036854775808 to 9223372036854775807.
Other constantsTRUE, FALSE, NULL
Comments-- to the end of the line and /* ... */
ErrorsSay where: line 1, column 22: ...

PartRules
TIMESERIES(col)Makes a time-series table. col is TIMESTAMP or DATE.
PARTITION BYTime-series only. Default DAY. Partition keys: '2026', '2026-09', '2026-09-10' (UTC).
SORT BYTime-series only. Default: first SYMBOL column, then the time column.
DEDUP KEYTime-series only. Must include the time column.
TTL n DAYSTime-series only. Partitions whose last moment is older than that are dropped by themselves. SET TTL NONE stops it. DROP PARTITION OLDER THAN does the same once, now.
TRUNCATERemoves every row, and keeps the table, its columns and indexes. Much faster than DELETE FROM t. Returns 1 table(s) truncated (57 row(s) removed). ROLLBACK cannot undo it, so it is refused inside BEGIN ... COMMIT. Needs the write role (TRUNCATE ALL TABLES: admin).
RECORDSSays "relational table" explicitly. Cannot be used with TIMESERIES.
PRIMARY KEYAt most one per table. Implies NOT NULL.
AUTOInteger PRIMARY KEY only. Next value from the table's counter, which only goes up (never reuses ids of deleted or rolled-back rows).
DEFAULTA constant or now(). No column names.
AS (expr)Computed column, not stored. Uses stored columns of the same row only. No DEFAULT, keys or REFERENCES. Cannot be set by INSERT/UPDATE.
REFERENCES t(c)t.c must be PRIMARY KEY or UNIQUE and of the same kind of type. Checked on INSERT and UPDATE. Without ON DELETE, a referenced row cannot be deleted; a referenced table cannot be dropped. REFERENCES t means t's PRIMARY KEY.
ON DELETE / ON UPDATENO ACTION (default), RESTRICT, CASCADE, SET NULL, SET DEFAULT. All changes of a statement are one transaction. Chapter 22.
PRIMARY KEY (a, b)Rows are stored by the key.
PostgreSQL type namesSERIAL, VARCHAR(n), NUMERIC(p,s), UUID, TEXT[], ... See Types and chapter 22.
ROUND intervalTIMESTAMP only. Cuts values down: ROUND 1m, ROUND 1d.
CHECK (condition)Checked for every written row (INSERT, UPDATE, upserts, InsertRows, line protocol). A row where it is false is refused; NULL passes. Only stored columns of the same row and built-in functions. Name when not given: table_column_check / table_check. ADD CHECK refuses when a row already breaks it. Chapter 15.
ADD COLUMN ... NOT NULLNeeds a DEFAULT.
DROP COLUMNNot for: the TIMESERIES column, SORT BY / DEDUP KEY columns, the PRIMARY KEY, referenced columns, columns used by computed columns or indexes, the only column.

Writing

[WITH name AS (query), ...]
INSERT [OR REPLACE | OR IGNORE] INTO table [AS alias] [(column, ...)]
VALUES (value, ...) [, (value, ...) ...] | SELECT ... | DEFAULT VALUES
[ON CONFLICT [(column, ...) [WHERE ...] | ON CONSTRAINT name]
   DO NOTHING | DO UPDATE SET column = expr, ... [WHERE condition]]      -- chapter 23
[RETURNING expr [[AS] alias], ... | *];

UPDATE table [[AS] alias] SET column = expr [, column = expr ...] [FROM source, ...] [WHERE condition] [RETURNING ...];

DELETE FROM table [[AS] alias] [USING source, ...] [WHERE condition] [RETURNING ...];

  • RETURNING gives rows like a SELECT: the inserted rows (with AUTO ids and defaults), the rows after an UPDATE, the deleted rows.

  • Values are constants or expressions without columns (now(), 1 + 1, CAST(...)), and subqueries.

  • ON CONFLICT, UPDATE ... FROM, DELETE ... USING, WITH x AS (UPDATE ... RETURNING ...) and subqueries (also correlated ones) in SET and WHERE: chapter 23.

  • There is no MERGE. To empty a table, use TRUNCATE (see Tables).

EXPLAIN SELECT ...;
RuleDetail
Implicit GROUP BYWith aggregates or SAMPLE BY and no GROUP BY, every select item without an aggregate is a group key.
SAMPLE BYTime-series tables (or subqueries with a TIMESTAMP column). The output time is the bucket start.
SAMPLE BY intervalsms, s, m, h, d, w, M (month), y (year). m = minute, M = month.
WEEK STARTOnly with a week interval. Default Monday.
ALIGN TO FIRST OBSERVATIONNot with TIME ZONE, WITH OFFSET, months or years.
FILLApplies to all aggregate columns. Fills only between the first and last bucket with data. At most 10 million rows.
LATEST ONOne table, no joins. Runs after WHERE.
ASOF JOINBoth sides need a time column. Takes the last right row at or before the left row's time.
ORDER BYOutput column name, alias, position (ORDER BY 2), or an expression. Default NULL position: NULLS LAST for ASC, NULLS FIRST for DESC.
UNION, INTERSECT, EXCEPTSame number of columns. Without ALL the rows are distinct. INTERSECT goes before UNION and EXCEPT. ORDER BY / LIMIT at the end apply to all rows and must use output names or positions.
Subqueries(SELECT ...) as a value (must return 0 or 1 row), IN (SELECT ...), EXISTS (SELECT ...), FROM (SELECT ...), LATERAL. They may use outer columns (correlated); inner.col = outer.col becomes a hash lookup (chapter 23).
Aggregatesagg(x) FILTER (WHERE cond), array_agg(x ORDER BY y), GROUP BY 1 (a select column), aggregates in ORDER BY and HAVING.
Window functionsWith GROUP BY or SAMPLE BY they run over the groups, one row per group. Their arguments must be aggregates or group keys: sma(last(close), 2), rank() OVER (ORDER BY sum(volume) DESC). sma(close, 2) there is an error (column 'close' is used by a window function in a query with aggregates, so it must be a key of the groups). Not inside each other (lag(sma(close, 3))): use a subquery.
Big GROUP BYWhen the groups need more than half of --max-result-memory, KarelaDB writes them to temporary files (_tmp/ in the database folder) and adds them up after the scan. The result is the same, only slower. At most 16 GB of such files per query.
SELECT without FROMAllowed: SELECT 1 + 1.

Views

CREATE [OR REPLACE] [CACHED] VIEW [IF NOT EXISTS] name AS [(] SELECT ... [)] [REFRESH ON COMMIT];
ALTER VIEW name AS SELECT ...;
REFRESH VIEW name;
DROP VIEW [IF EXISTS] name;
CREATE MATERIALIZED VIEW [IF NOT EXISTS] name [PARTITION BY DAY | MONTH | YEAR] [TTL n DAYS]
  AS SELECT time_bucket, ..., aggregates FROM table GROUP BY time_bucket, ...;
REFRESH MATERIALIZED VIEW name [FOR 'time' [TO 'time']];
DROP MATERIALIZED VIEW [IF EXISTS] name;
SHOW VIEWS;
KindWhat it keeps
ViewNothing. Its query runs every time you use it.
CACHED viewIts rows, in memory. Made at CREATE and at REFRESH VIEW; with REFRESH ON COMMIT again at the first read after a commit changed one of its tables. CREATE says view 'name' created (4 row(s) cached).
MATERIALIZED viewA real table with the result of a GROUP BY over one time-series table. After each commit, a background thread rebuilds only the partitions that changed. The GROUP BY must have a time bucket: the time column, to_date(time) or date_trunc('day', time).

REFRESH ON COMMIT needs CACHED. A view and a table cannot have the same name.

Indexes and full-text search

Chapter 17 explains them with a forum and a news example.

CREATE [UNIQUE | FULLTEXT] INDEX [IF NOT EXISTS] name ON table (column, ...);
CREATE [UNIQUE] INDEX [CONCURRENTLY] [IF NOT EXISTS] [name] ON [ONLY] table [USING method]
  ({column | (expression)} [DESC] [NULLS LAST], ...) [WHERE condition];   -- PostgreSQL form, chapter 22
DROP INDEX [IF EXISTS] name;
SHOW INDEXES [FROM table];   -- columns: name, table, kind, columns, built, rows, memory_bytes, create_sql
RuleDetail
NameUnique in the database.
Columns1 to 16 stored columns (not computed). Relational and time-series tables.
UNIQUETwo rows cannot have the same values. NULL values never clash. Error: duplicate value violates unique index 'name' on table 't': a row with col='value' already exists. Creating it fails when rows already clash.
FULLTEXTSTRING, SYMBOL or JSON columns. Used by MATCH(...), search_rank(...).
Where the data livesIn memory only. kareladb serve builds it from the rows right after the database opens, on a background thread. In kareladb sql, kareladb shell and with --warm-indexes off, the first query that needs it builds it. CREATE INDEX builds it at once. Nothing on disk: crashes, kareladb check, kareladb repair, backups need nothing extra.
When a query uses an indexcol = value, col IN (...), col IS NULL on the first columns, then a range (<, <=, >, >=, BETWEEN, LIKE 'abc%', time IN '...', a row comparison) on the next column. ORDER BY the next columns (all ASC or all DESC) with LIMIT reads only the rows needed. MATCH uses a FULLTEXT index on the same columns. EXPLAIN shows use index name (...). Also used by UPDATE and DELETE.
When it does notA condition with OR, a function around the column, !=, NOT LIKE, a FLOAT column, text compared with a number, or when the index would read more than a quarter of the table.
DROP COLUMNRefused while an index uses the column. RENAME COLUMN / RENAME TABLE keep the index. DROP TABLE drops its indexes.
Expression and partial(lower(email)), WHERE is_default. A UNIQUE one is checked on every write. A non-unique one is used by a query that asks for the same thing: lower(email) = 'a@x.np', or a WHERE that has every part of the index's own WHERE.
Not in a transactionCREATE INDEX and DROP INDEX cannot be used between BEGIN and COMMIT.

Sequences

CREATE SEQUENCE [IF NOT EXISTS] name [INCREMENT [BY] n] [MINVALUE n] [MAXVALUE n] [START [WITH] n] [[NO] CYCLE];
ALTER SEQUENCE name [RESTART [WITH n]] [INCREMENT [BY] n] ...;

A number is never given twice, also after a crash. currval and lastval are per session.

Functions, procedures and triggers

Chapter 13 explains them with examples.

CREATE [OR REPLACE] FUNCTION name(param TYPE, ...) [RETURNS TYPE] AS (expression);
DROP FUNCTION [IF EXISTS] name;
SHOW FUNCTIONS;                         -- columns: name, arguments, returns, definition

CREATE [OR REPLACE] PROCEDURE name(param TYPE, ...) AS BEGIN
  statement; ...
END;
CALL name(argument, ...) [WITH DEBUG];
DROP PROCEDURE [IF EXISTS] name;
SHOW PROCEDURES;                        -- columns: name, arguments, definition

CREATE [OR REPLACE] TRIGGER name {BEFORE | AFTER} {INSERT | UPDATE | DELETE} ON table
  EXECUTE {CALL procedure(argument, ...) | INSERT ... | UPDATE ... | DELETE ... | BEGIN statement; ... END};
ALTER TABLE table {ENABLE | DISABLE} TRIGGER name;
DROP TRIGGER [IF EXISTS] name;
CREATE [OR REPLACE] TRIGGER name AFTER INSERT ON table DEFERRED [TIMEOUT 10min] EXECUTE ...;
RETRY TRIGGER QUEUE name;               -- a DEFERRED trigger: run the failed job again
SKIP TRIGGER JOB name job_id;           -- a DEFERRED trigger: leave one job out
SHOW TRIGGERS;                          -- columns: name, table, timing, event, enabled, definition

Statements inside a procedure or trigger body (each ends with ;):

SELECT ... | INSERT ... | UPDATE ... | DELETE ... | CALL name(...) | SHOW ... | EXPLAIN ...
DECLARE variable TYPE [DEFAULT expr]
SET variable = expr                     -- also: SET variable = (SELECT ...)
IF condition THEN ... [ELSIF condition THEN ...] [ELSE ...] END IF
WHILE condition DO ... END WHILE
FOR row IN (SELECT ...) DO ... END FOR  -- row.column is a value of the current row
DECLARE cursor CURSOR FOR SELECT ...
OPEN cursor
FETCH cursor INTO variable, ...        -- sets the variable FOUND
CLOSE cursor
RETURN
RAISE expr                              -- error: the whole CALL (or statement) is undone
PRINT expr                              -- a line in the "print" (or "debug") result
RuleDetail
Function bodyOne expression using only its parameters. No subqueries, aggregates or window functions. Not in computed columns. The name cannot be a built-in function.
Names in a bodyA column name wins over a variable or parameter with the same name.
CALLOne transaction. Its SELECTs return extra results; PRINT adds a print result; WITH DEBUG adds a debug result (step, routine, statement, rows, time_us, changes).
TriggersOnce per statement (also once per InsertRows call and POST /write request), in the same transaction. The body reads the tables NEW and OLD.
DEFERREDOnly AFTER INSERT. Runs after the commit, as a background job of the server; the insert does not wait. Chapter 13.
DROP TABLE, RENAME TABLERefused while the table has triggers.

Transactions and cursors

BEGIN [TRANSACTION | WORK];
COMMIT [TRANSACTION | WORK];
ROLLBACK [TRANSACTION | WORK];

DECLARE name CURSOR FOR SELECT ...;     -- runs the query and keeps the rows
FETCH [NEXT [n] | ALL] FROM name;       -- NEXT without n = 1 row
CLOSE name;
RuleDetail
ScopeA transaction and a cursor end with the text they were sent in (kareladb sql, /exec, the web console). In a session (kareladb shell, POST /session + X-KDB-Session, a PostgreSQL connection) they stay open over many requests. A text without a session that ends without COMMIT is rolled back with an error.
ErrorsA failing statement rolls back the whole open transaction. In a session, only ROLLBACK (or COMMIT, which then fails) is accepted after that.
Many writersWriters of different tables run at the same time; writers of the same table take turns: they wait up to 5 s (table 'x' is busy), and two transactions that would wait for each other get deadlock at once. Readers see the committed rows. An idle transaction is rolled back after 30 s. Chapter 15.
Not in a transactionCREATE, DROP, ALTER, RENAME, TRUNCATE, BACKUP DATABASE.
HTTPPOST /cursor, GET /cursor/<id>?fetch=N, DELETE /cursor/<id> (chapter 8).

BACKUP DATABASE;          -- needs --backups <folder> on kareladb serve / shell / sql
CHECK TABLE any_name;     -- reads every file of the whole database

Databases

A database is a folder in the data folder (chapter 1). Each database has its own tables, views, triggers and procedures.

CREATE DATABASE [IF NOT EXISTS] name;
DROP DATABASE [IF EXISTS] name;     -- closes it and moves its folder to <data folder>/_trash
SHOW DATABASES;                     -- columns: name, tables, bytes, current
USE name;                           -- the statements after it use this database
SELECT ... FROM other_db.table ...; -- read a table of another database on the same server
RuleDetail
NamesLetters, digits, _ and -, 1 to 64 characters. Market and market are the same database. The folder keeps the name as you first wrote it. Not allowed: _trash and the Windows device names CON, PRN, AUX, NUL, COM0-COM9, LPT0-LPT9.
DROP DATABASERefused while another request or shell uses the database. Nothing is deleted: the folder moves to _trash/<time in ms>-<name>. To get it back, stop the server and move the folder back.
database.tableReads a table of another database: SELECT, joins, subqueries, INSERT INTO t SELECT ..., CREATE TABLE t AS SELECT .... A statement only changes the database it runs in. Works over HTTP, the PostgreSQL port, kareladb shell and the console.
USEIn kareladb shell: stays until the next USE. Over HTTP: only for the rest of that request; choose the database of a request with db=<name> (chapter 8).
Where they workkareladb shell and kareladb sql with a database name (or no name), and kareladb serve with a data folder. A command that opened one folder by its path (kareladb serve D:\kdb\market) cannot create or drop databases.
@"
CREATE DATABASE IF NOT EXISTS market;
CREATE DATABASE demo;
USE demo;
CREATE TABLE notes (id INT PRIMARY KEY, text STRING);
SHOW DATABASES;
USE market;
DROP DATABASE demo;
DROP DATABASE IF EXISTS demo;
SHOW DATABASES;
"@ | kareladb shell --data-dir kdb-data

End statements with ';'. Type .help for commands, .exit to quit.

Users and roles

Users of the KarelaDB server (chapter 16). They belong to the data folder, not to one database.

CREATE USER [IF NOT EXISTS] name [WITH] PASSWORD 'secret' [ROLE admin|write|read|none];
ALTER USER name [WITH] PASSWORD 'new secret';
ALTER USER name ROLE read;
DROP USER [IF EXISTS] name;
SHOW USERS;                                              -- columns: name, role, grants, created, changed
GRANT read|write|admin|ALL ON DATABASE db TO name;       -- ALL = admin
REVOKE [read|write|admin|ALL] ON DATABASE db FROM name;
RoleStatements
readSELECT, SHOW, EXPLAIN, BEGIN/COMMIT/ROLLBACK, DECLARE/FETCH/CLOSE
write+ INSERT, UPDATE, DELETE (also with RETURNING), TRUNCATE, CALL, SELECT ... FOR UPDATE
admin+ CREATE/ALTER/DROP/RENAME of tables, views, indexes, functions, procedures, triggers; BACKUP DATABASE; CHECK TABLE
ROLE admin (own role)+ CREATE/DROP DATABASE, all user statements
RuleDetail
Namesletters, digits, _ and -, 1 to 63 characters; not case sensitive
Passwords8 to 1024 bytes. Shown as '***' in every statement KarelaDB shows back.
First usermust have ROLE admin. From then on the server asks for a login.
Last admincannot be dropped or lose ROLE admin while other users exist
Own passwordevery user may run ALTER USER <own name> WITH PASSWORD '...'
SHOW USERSnever shows passwords or hashes; a user who is not an admin sees only their own row
kareladb shell, kareladb sqlopen the files directly and do not check users

Correlated subqueries

SELECT s.symbol, (SELECT max(close) FROM ochl_day d WHERE d.symbol = s.symbol) AS best FROM securities s;

The subquery uses s.symbol of the outer row. KarelaDB does not run it once per row: it reads ochl_day once, groups it by symbol, and looks every security up in that result. Chapter 23 has the rules.

Try it yourself

  1. What is the result of SELECT 10 / 4, 10 % 4, round(10 / 4)?
  2. Write the number of whole days between 2026-01-01 and 2026-09-10.
  3. Which of these names need double quotes: time, order, left, select, symbol?
Answers
  1. 2.5, 2, 3.
  2. SELECT datediff('d', '2026-01-01', '2026-09-10') gives 252.
  3. order and select always. left only as a short alias without AS. time and symbol never.
